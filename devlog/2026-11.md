## 2026-11-01: TelemetryDeck analytics, full event set, opt out (Android)

**What changed**
- Android twin of iOS `e2a1b09` to `4ffa1a0`: the same event names, parameters and values as the Notion Analytics Events page
- New `Analytics.kt`, the only file that calls the SDK; started in `QwavaApplication` after Firebase; `qwava_analytics_enabled`, on by default
- Debug builds send test signals and log every event with its parameters under the `QwavaAnalytics` Logcat tag
- Sharing: `Share.opened` with a source per caller; `Question.shared` from `ShareResultReceiver`; `WhoPrompt.answered`; `PersonSetting.saved` source shareScreen
- Getting around: `Tab.opened`, `Deck.opened` with a source, `QuickMix.created`, `Search.resultOpened`, `Home.filtersApplied`, `Home.sortChanged` (menu, tap)
- Player: `Deck.played`, `QuickMix.played`, `Deck.finished`, `DepthFilter.changed`, `Question.saved`, `Deck.bookmarked`
- Recommendations: `Recommendation.shown`, `.opened`, `.another`
- People: `Person.opened`, `PersonSettings.opened`, `PersonSetting.saved`, `Ask.answered`, `FollowUp.action`, `Nudge.shown`, `Nudge.action`
- Notifications and account: `Notification.tapped`, `Notifications.changed`, `Notifications.permissionDenied`, `Account.signedIn`, `Language.changed`
- Opt out: "Help improve Qwava" in the More settings card after Vibrations; off sends `Analytics.disabled`, then `TelemetryDeck.stop()`; on starts the SDK again
- Restart on the end screen starts a new play session, as on iOS: a replay counts as its own play
- `strings.xml` in both languages regenerated from the iOS catalog, two new keys
- Commit `682866d`

**Key decisions**
- Kotlin SDK 6.2.0: 7.x is built with Kotlin 2.3 and hit an internal compiler error against the project's 2.2.10
- The Kotlin SDK has no live off switch like `analyticsDisabled`; `stop()` drops the instance and its lifecycle observers, `start()` builds a new one
- `stop()` runs on the main thread (the first build crashed removing observers from a background thread) and is skipped when the switch went back on meanwhile
- `Analytics.disabled` goes out through the SDK's immediate send with a 3 second cap
- Shown events through a new `onHalfVisible` modifier in `HalfVisible.kt`: half the card on screen, same threshold as iOS
- `PendingPlayerStore.openSource`, consumed once per open, so a rotation never counts a second `Deck.opened`; openers without a source count as other
- `Person.opened` once per visit through a saveable flag in the route; the source is set by the tap in `Analytics.pendingPersonSource`
- The play report is kept apart from the play stats, so Quick Mix sends `QuickMix.played` and still never counts as a played deck
- `Question.shared` reports sent or saved when the chooser names the app; a dismissed chooser reports nothing on Android, so result cancelled is iOS only
- No shake on Android, so `Home.sortChanged` via shake is iOS only; `TableMode` events skipped
- TelemetryDeck's auto start provider removed from the manifest, so `Analytics.start()` is the only way analytics starts

**Files changed**
- `Analytics.kt` (new), `HalfVisible.kt` (new), `QwavaApplication.kt`, `PendingPlayerStore.kt`, `PlayStatsStore.kt`, `ShareResultReceiver.kt`, `AuthStore.kt`, `NotificationTapRouter.kt`

**Unresolved**

- A rotation while Filters or a person's settings are open counts one extra close
