## 2026-08-09: Sign out sync fix and a data loss incident (iOS)

**What changed**
- `CloudSync.swift`: new `flushBeforeSignOut()` pushes all five stores while the user is still authenticated; guarded by `localHasActivity()` so an empty device can never overwrite a populated cloud.
- `AuthStore.swift`: `signOut()` awaits the flush before `GIDSignIn.signOut()` and `Auth.signOut()`.
- `CloudSync.swift`: `signedOut(previousUID:)` no longer pushes and no longer guards the wipe; it clears local unconditionally.
- `SpaceFollowUpCard.swift`: removed the placeholder comment on the follow up subline; the colon version is approved.

**Key decisions**
- Flush before sign out, not after: the auth listener fires once the token is gone, so every write from `signedOut` was denied.
- One place responsible for the final push. The old `guard stats, favs, saved, sent, people else { return }` could never pass, so sign out never wiped the device, contradicting the August behaviour.
- `localHasActivity()` guard added after the incident below; a push is a whole document overwrite, so an empty local state is destructive.

**Incident**
- Removing the unreachable guard let the wipe run; a later push wrote the emptied state over `users/{uid}`, clearing favorites, play stats, sent history and people on the test account.
- Point in time recovery unavailable on Spark, and it only retains from activation, so no rollback path.
- Recovered by opening the Android build, whose `signedIn` takes the silent migration path when the cloud is empty (`cloudHasData` false) and pushed its local copy back up; an iOS pull to refresh then restored the device.
- Firestore console offers no export on Spark; the delete entries in its menus are the only actions there.

**Files changed**
- `CloudSync.swift`, `AuthStore.swift`, `SpaceFollowUpCard.swift`

**Unresolved**
- Airplane mode test not run: sign in offline so local stays empty, sign out, confirm the cloud survives. The guard is untested.
- Offline sign out still wipes the device with nothing flushed, so unsynced activity is lost; wants a warning or a deferred flush.
- Whether `localHasActivity()` belongs on the other push paths, including `startPushing` and the refresh, is unreviewed.
- Two device sync verification still open, now the last gate before release.

## 2026-08-10: Cloud sync push gate, offline sign out, launch routing (iOS)

**What changed**
- `CloudSync.swift`: new `pulledUID` records the account whose cloud copy has been read this session; all five `push*` functions return early unless it matches the signed in uid.
- `CloudSync.swift`: `signedIn` sets `pulledUID` immediately after `getDocument()` succeeds, before the keep or leave return, since `resolvePendingMerge` pushes.
- `CloudSync.swift`: the failed pull path no longer calls `startPushing()`; new `retryPullIfNeeded()` retries on foreground, wired to `scenePhase` in `QwavaApp.swift`.
- `CloudSync.swift`: `pushAll` returns Bool; `flushBeforeSignOut(timeout:)` returns whether the flush was acknowledged, racing the push against a three second deadline via a new `FlushOutcome` actor.
- `CloudSync.swift`: `handleAuthChange` waits 500ms and confirms `Auth.auth().currentUser == nil` before treating a nil user as a sign out.
- `CloudSync.swift`: the keep or leave condition now requires `localDataOwner != nil`, so a reinstall of the same account merges silently.
- `AuthStore.swift`: `signOut(force:)` is async and returns false without signing out when the flush did not confirm; new `hasResolvedInitialAuth` published on the first listener callback.
- `MoreView.swift`: sign out no longer clears the five stores itself; awaits `signOut()`, shows a spinner overlay, and presents a second alert after a 400ms delay when the flush failed.
- `RootView.swift`: holds `LaunchScreen.storyboard` via `UIViewControllerRepresentable` until auth reports; a live session overrides `hasSeenOnboarding` and `hasEnteredApp`; `onChange(of: auth.isLoggedIn)` marks onboarding seen.
- `QuestionPlayerView.swift`: `RemoteSmallCover` falls back to the bundled asset; `.id(idx)` added to the retry view so `onAppear` fires per extension.
- `FlatNavBar.swift`: nav bar appearance sets Inter at weight 400 for large and inline titles; `InterVariableSupport.swift` gains a `UIFont.interVariable` builder that `Font.interVariable` now wraps.
- Twelve button labels across nine screens set `BrandFont.body(weight: .regular)`.

**Key decisions**
- Gate all pushes on a successful read rather than guarding each push on local emptiness: a push is a whole document overwrite, so the only safe precondition is knowing what the cloud holds.
- `withTaskGroup` rejected for the flush timeout: it waits for every child, and an offline Firestore write never returns.
- The sign out warning names the account as unreachable rather than the device as offline, since a server error or expired token fails the flush identically.
