## 2026-04-08 — Android: Project Setup + Data Layer

### Setup
- Android Studio installed on Mac (Apple Silicon)
- Project created: package `com.qwava.app`, minimum SDK API 26, Jetpack Compose with Kotlin DSL
- Folder structure: models, data, ui/screens, ui/components, ui/theme
- Firebase connected: same project as iOS (eur3 region), `google-services.json` in app folder, internet permission added

### Models converted from Swift to Kotlin
- `Deck.kt`, `Filters.kt`, `QuestionItem.kt`, `DeckID.kt`
- Gson used for JSON parsing (equivalent of Swift Codable)
- Filter fields in Deck stay as `List<String>`; enum conversion happens in the UI layer

### Data layer
- `DeckStore.kt`, `QuestionStore.kt`, `RemoteContent.kt`, `RemoteContentManager.kt`
- `decks.json` and `questions.json` copied to `app/src/main/assets/`

### Key Swift to Kotlin mappings
- `Bundle.main` → `context.assets`
- `@Published + ObservableObject` → `StateFlow`
- `static let shared` → companion object singleton
- `UserDefaults` → `SharedPreferences`
- `FileManager.Documents` → `context.filesDir`
- `FileManager.Caches` → `context.cacheDir`
- `CryptoKit SHA256` → `java.security.MessageDigest` (same output, cross-platform compatible)

## 2026-04-20 — watchOS v1: QwavaWatch App

### What was built
- New target: QwavaWatch Watch App, watchOS deployment, bundle `com.rafdesign.QwavaWatch`
- `QuestionItem.swift` target membership ticked to include watch target
- `WatchStore.swift` — Fetches `questions.json` directly from CDN. `WatchParticipants`, `WatchFamiliarity`, `WatchDepth` enums. `@AppStorage` for settings. `pickRandom()` filters by depth only. `@MainActor + ObservableObject`.
- `WatchQuestionView.swift` — ScrollView, tap anywhere to advance, settings icon bottom-right
- `WatchSettingsView.swift` — Three pickers (Depth, Participants, Familiarity), Apply and Close buttons
- `QwavaWatchApp.swift` — NavigationStack wrapping WatchQuestionView

### Key decisions
- Fully standalone, no WatchConnectivity, no Firebase. Fetches from CDN directly.
- Tap to advance replaces shuffle button (correct watch interaction pattern)
- `@StateObject` used instead of `@ObservedObject` for singleton stability
- Watch app ships bundled inside iOS submission; cannot be submitted separately
- WatchConnectivity deferred to v2
- Depth is the only active filter for v1; participants and familiarity shown in UI but not wired

### Bugs fixed
- `WatchStore` missing `import Combine` caused `@Published` and `ObservableObject` errors
